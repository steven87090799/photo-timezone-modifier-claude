Pipeline 執行管線

  • 優先權排程 小體積 JPEG 先跑、巨檔與 HEIC/AVIF 靠後——進度條從一開始就有東西動,不會全部卡在最慢那張。
  • 記憶體防護 同時在編碼的原始檔總量超過 200MB 時自動減半並行、超過 400MB 降為單工,壓完自動恢復。大批 5000 萬像素的圖也不會把分頁撐爆。
  • 崩潰自癒 單一 Worker 崩潰會原地重生並自動重試該任務一次;重複崩潰觸發斷路器,明確報錯而不是無聲卡死。
  • 壞檔隔離 解不開的檔案進 Dead Letter Queue,不中斷批次;結束後可一鍵匯出含失敗原因的 JSON 報告。

Large Batch 實務建議

  • 幾百張手機照 → JPEG/WebP + 3-5 執行緒
  • 大量 HEIC 轉檔 → 執行緒 2-3(解碼吃記憶體)
  • AVIF 批次 → 睡前掛機,別開 10 執行緒
  • 多檔下載自動打包成單一 ZIP

Format Guide 格式選擇指南

  • JPEG 相容性之王。任何裝置、平台、印刷流程都收。交件給客戶、上傳社群、不確定對方環境時的安全預設。品質 90+ 自動切換 4:4:4 色度取樣，保住紅字與飽和色邊緣。
  • PNG 無損。截圖、圖表、UI 素材、需要透明背景的圖。品質滑桿控制的是壓縮努力度（不影響畫質），照片類轉 PNG 通常會比來源更大。
  • WebP 網站主力。同畫質下比 JPEG 小 25-35%，所有現代瀏覽器都支援。恆開 Sharp YUV 轉換，色彩邊緣乾淨。網站素材、部落格圖床首選。
  • AVIF 壓縮率天花板，但每張編碼 10-60 秒。適合「壓一次、用很久」的場景：網站 hero 圖、長期封存的最終交付版。
  • HEIF Apple 生態工作流。macOS 原生 HEVC 編碼，品質可調，並由 ImageIO 解碼產生縮圖。
  • JXL 封存格式。品質 100 = 像素完全無損；低於 100 為有損模式。若無損模式中止，系統會換新編碼器並以 99 近無損重試，結果會明確標示。注意：此編碼器不嵌入 EXIF/ICC，且多數瀏覽器尚無法預覽。

Engine 技術架構

  • MozJPEG progressive + trellis 最佳化
  • OxiPNG 無損 PNG 重壓
  • libwebp method 6 + Sharp YUV
  • libaom AVIF / SSIM 感知調校
  • libjxl JPEG XL 含無損模式
  • macOS ImageIO 原生 HEVC → HEIF 容器，並處理 HEIC 輸入

JPEG、PNG、WebP、AVIF、JXL 使用 WebAssembly 與 Web Worker；HEIF 由 App 的原生背景工作佇列處理。

Privacy 隱私承諾

檔案只在這台 Mac 的 App、Web Worker 與回環位址間處理；沒有產品遙測或 CDN 請求。唯一會傳送輸出檔案的功能是你主動設定並啟用的 Webhook 匯出，它只會送到你指定的伺服器，Bearer token 僅保留於目前工作階段。App 內建所有執行資產，可離線使用。

Metadata 保留行為

  • JPEG 來源 → JPEG 輸出 複製現有 EXIF、ICC、XMP APP 區段；無法注入時該張輸出失敗。
  • JPEG 來源 → WebP 輸出 EXIF、ICC、標準 XMP 依 RFC 9649 重組寫入；延伸 XMP 無法安全重組時該張輸出失敗。
  • Orientation 像素已在解碼時轉正,EXIF 方向值同步重設,不會出現雙重旋轉
  • AVIF / JXL / HEIF / PNG 目前不注入來源 EXIF／ICC／XMP；不得視為保留時區與 GPS。HEIF 由 ImageIO 編碼為 sRGB。

FAQ 常見問題

  • 為什麼 AVIF 這麼慢? libaom 以窮舉搜尋換壓縮率,這是格式特性不是 bug。趕時間用 WebP,要極致體積用 AVIF。
  • HEIC 檔案可以當輸入嗎? 可以。iPhone 的 .heic/.heif 會先在背景解碼再轉入任何輸出格式,EXIF 一併從 ISOBMFF 容器提取。
  • 預估大小準嗎? 預估來自解析曲線 × 複雜度取樣 × 你的歷史壓縮記錄(存在本機 localStorage),越用越準;實際結果以壓縮完成為準。
  • 批次中有壞檔會怎樣? 單一損毀檔案會被隔離到 Dead Letter Queue,批次照常完成,結束後可匯出 JSON 錯誤報告。
  • 輸出檔名規則? 同格式保留原檔名(含大小寫);跨格式只換副檔名,主檔名原樣保留。
