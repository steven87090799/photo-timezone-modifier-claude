# 相片時區修改器 3.2

SwiftUI 原生 macOS App，為 ARW、JPEG、TIFF 相片補上 EXIF 時區偏移，支援背景處理、逐檔報告、備份與復原。由原本的 AppleScript droplet 改寫；舊版程式保留在 legacy/，新版 App 不會執行舊程式。

## 使用方式

1. 開啟「相片時區修改器.app」，加入相片或資料夾，也可直接拖放。
2. 拖入後會自動以唯讀方式掃描。先看縮圖、相機／鏡頭、拍攝時間與現有時區，再決定要不要改；可切換是否包含子資料夾。
3. 選擇固定 UTC 偏移（預設 +08:00）；提供 −12:00 到 +14:00、每 15 分鐘一格。
4. 預設關閉「替換來源資料夾中的原照片」，選一個獨立的目的資料夾輸出副本；若打開開關，才會以同格式成品替換來源檔案，並逐張保留替換前版本。RAW 不會轉成 JPEG。
5. 選擇「全部預覽」「篩選結果」或「手動選取」的處理範圍。按「檢查並寫入」後確認張數、偏移、位置及寫入方式，才會真正修改。預設只補缺漏，保留既有時區。
6. 處理時有張數、百分比、成功／失敗／略過與粗略剩餘時間。報告列出逐張失敗原因；可只重新檢查失敗／取消項目，確認後再重試寫入。也可匯出完整紀錄。

選項是固定 UTC 偏移，不會根據城市、拍攝日期或夏令時間自動換算。同批相片若跨越不同偏移，請分開處理。程式不改動 EXIF 的 DateTimeOriginal、CreateDate、ModifyDate，寫入後會重新讀取確認。

## 大量相片與資訊確認

- 本工具不做 RAW 轉 JPEG；ARW／JPEG／TIFF 維持原格式，只修改 EXIF 時區標籤。
- 顯示相機廠牌／型號、鏡頭型號、ISO、快門、光圈、焦距、尺寸、檔案大小、拍攝時間及三個時區。相機未記錄的欄位會顯示缺少，絕不猜測。
- 可搜尋檔名／路徑、相機、鏡頭、日期；依相機、缺時區、時區完整、失敗或取消篩選；按檔名、時間、相機或大小排序。
- 每頁最多 200 張，搜尋／篩選涵蓋整批。Shift／Command 複選；「選取篩選結果」包含全部符合的頁面，不只目前頁。
- 點選相片可看小縮圖與基本資訊；一次僅解碼一張、最多快取 8 張 480px 縮圖，不為數千張相片同時載入原圖。部分 RAW 無可讀縮圖時仍可查看 EXIF，或用「快速查看」開啟預設影像程式。
- 進度顯示百分比、成功／失敗／略過數、已用時間與粗略剩餘估計。失敗／取消可單獨重新檢查，重新確認後再寫入；不會自動重寫已成功的項目。App 關閉後可重新匯入資料夾；替換模式的「只補缺漏」會略過時區完整的原檔，副本模式則仍會輸出完整批次，但遇到既有同名輸出會報錯、不覆蓋。目前沒有跨重啟的工作佇列續跑。
- 建議先把記憶卡檔案複製到電腦或可寫入的工作磁碟，再匯入；不會自動移動或刪除你的相片。

## 輸出、備份與復原

- 副本模式會在你選的獨立目的資料夾保留來源資料夾名稱和相對路徑；單獨選取的檔案放在目的資料夾頂層。來源完全不修改；同名衝突逐張失敗、不覆蓋既有輸出。已完整填好時區的來源仍會原樣複製，使目的資料夾是一批完整副本。
- 替換模式每張先在同一資料夾建立隱藏候選副本，由 ExifTool 只在候選副本上寫入；檢查三個時區、拍攝時間、其餘可讀中繼資料與檔案屬性，再建立並同步可復原備份，最後用同資料夾的原子 rename 替換原檔。
- 第一次替換保留「原檔名_original」；再次替換會額外保留「原檔名.before-write-UUID.backup」，原始的 _original 永遠不覆蓋。
- 「從原始備份還原」會先另存當前版本為「原檔名.before-restore-UUID.backup」，以同樣的暫存／驗證／原子替換流程復原；_original **不會消耗**，可繼續使用。
- .backup、_original 與隱藏候選檔不會被當成相片重新掃描。替換與復原需足夠空間容納候選檔、ExifTool 暫存與備份；副本模式需容納候選檔與 ExifTool 暫存。
- 若原檔遺失但 _original 還在，掃描會顯示可還原的遺失檔案；還原會重建原檔並保留該備份。
- 候選檔會保留檔案系統建立／修改時間、權限與延伸屬性，驗證不符就不提交。ExifTool 可讀的非時區內嵌標籤會逐項比較；TIFF 因 EXIF 區塊擴張而可能變動的 StripOffsets 位址指標除外。這是語意層級的檢查，不表示整個檔案除了時區位元組外都不變。
- 同資料夾原子替換與檔案／目錄同步能降低程式或系統中止造成的遺失風險：替換前原檔仍在，替換後備份仍在；中途遺留的隱藏暫存檔不會自動當成相片處理。仍無法保證磁碟／記憶卡損毀、控制器不遵守同步指令或外部程式同時改檔時絕對零損失；重要照片請另存第二份實體備份。

## 穩定性

- 直接使用 FileManager 掃描資料夾，無需控制 Finder。跳過隱藏檔、套件與符號連結；重複路徑只處理一次。
- 掃描以最多 48 張／96 KiB 路徑分批讀取，避免每張重新啟動引擎；JSON 依 SourceFile 對應結果，不依回傳順序。寫入仍背景逐張處理、逐張驗證，沒有整批 Shell 字串或參數檔跳脫問題。
- 相片結果先在背景事件緩衝區累積，介面約每 150 毫秒合併更新，避免每張相片都觸發整個清單重繪。
- 每張相片都獨立檢查，第一張損壞不會中止其他相片。格式依實際內容再驗證。
- 直接解析 ExifTool JSON、退出狀態與錯誤訊息；警告會保留在每張相片的結果。
- 取消會完成正在處理的相片，再略過後續工作；不強制中斷正在寫入的 ExifTool。單一大型檔案或慢速磁碟可能需要等候。
- ExifTool 單次讀取（單張或一批）可取消，上限 120 秒；只對可丟棄的候選副本設定 600 秒寫入上限，逾時時原檔不會被 ExifTool 直接操作。非標準位置或重複出現的時區標籤會報錯並保留原檔。
- 每張寫入前檢查可寫入性與可用空間（替換模式保守預留該張大小的四倍再加 32 MiB，副本模式三倍）；不足則不開始該張寫入。這不是保證後續磁碟不會被其他程式用滿。
- 同一使用者的多個 App 副本不允許同時執行處理工作；其他軟體修改同一檔案不在此鎖定範圍。
- 紀錄逐檔寫入本機 ~/Library/Application Support/PhotoTimezone/Logs/，包含檔案路徑與中繼資料，不會上傳。若紀錄無法寫入，後續工作會停止。

## 建置與測試

需要 macOS 13+、Swift 5.9+（Xcode 或相容的 Command Line Tools）與 /usr/bin/perl。專案沒有線上 Swift 套件依賴。

    ./build.sh

建置結果位於 dist/相片時區修改器.app，架構為本機架構。Apple Silicon 與 Intel 通用版：

    ./build.sh --universal

建置先驗證 vendor/ 中 ExifTool 13.59 的 SHA-256，然後將完整引擎與授權文件包入 App；使用者執行 App 不需下載引擎，也不會自動採用 Homebrew 或舊版可攜引擎。

    ./scripts/test.sh

額外的 1,000 張混合 JPEG／TIFF 替換與備份完整性測試，以及 1,000 張 JPEG 副本輸出測試（各會花數分鐘，所有素材均自動產生）：

    PHOTO_TIMEZONE_STRESS=1 ./scripts/test.sh --filter testThousand

GitHub Actions 的手動執行也可勾選 `stress`；一般 PR 流程只跑快速回歸測試。請勿同時在 App 中啟動處理，測試與 App 共用防止重複處理的工作鎖。

測試使用 Swift Testing（需要 Swift 6+ 與相容的 macOS／SDK），使用自動產生的小型 JPEG／TIFF，不修改使用者相片。另可透過 TEST_EXIFTOOL_PATH 指定測試引擎路徑，但版本仍須吻合。原生 App 可直接以 Package.swift 在 Xcode 開啟編輯；直接 swift run 不包含 App bundle 的 ExifTool 資源，完整使用請透過 build.sh。

目前建置採本機 ad-hoc 簽章，尚未以 Developer ID 簽署或送 Apple 公證。正式散布到其他電腦前需要完成該發行流程。系統 Perl 的可用性會在啟動處理時檢查。

## 專案結構

- Sources/PhotoTimezoneApp/：SwiftUI 介面、進度、拖放、選檔與報告。
- Sources/TimezoneCore/：檔案探索、背景工作、ExifTool、備份與復原。
- Tests/TimezoneCoreTests/：單元與真實 ExifTool 整合測試。
- app/Info.plist：原生 App 資訊與文件類型。
- app/Assets/：黑銀色「相片＋時鐘」圖示、原始 PNG 與生成提示詞；建置時轉成 macOS ICNS。
- vendor/：固定版 ExifTool 原始碼封存檔、來源 commit 與 SHA-256。
- legacy/：原 AppleScript 歷史版本；僅供參考。

第三方授權見 THIRD_PARTY_NOTICES.md 與 App 資源內的 ExifTool 文件。

已完成的測試與尚未驗證的範圍見 [VALIDATION.md](VALIDATION.md)。
